# 登录后生物数据光谱背景设计

## 目标

为登录后的管理后台增加具有品牌辨识度的全局背景，减少大面积空白带来的空旷感，同时保持表格、表单、地图和业务面板的可读性与高频操作效率。

本设计仅作用于认证后的应用壳层。沉浸式登录首页及其现有 Three.js 场景保持不变。

## 设计方向

采用“多股生物数据流组成的大型对角丝带”：以浅灰白底色为基础，让一条由 6 至 12 股半透明数据流组成的宽阔轨迹从偏左上进入，经屏幕中部延伸至偏右下，并叠加极淡的分子节点、数据连线、网格或等高线纹理。

该轨迹覆盖整个工作区的构图范围，但不铺满整个屏幕。主体约占视口面积的 25% 至 35%，沿途保留足够负空间和内容可读区域。整体参考 Stripe 使用大尺度非对称视觉主体组织空间的思路，但配色、纹理和状态变化围绕生物医药数据系统重新设计，不直接复制 Stripe 图形。

丝带近看并非一块普通彩色平面，而是由 DNA 链、光谱曲线、传感器数据流和溯源轨迹构成。约 30% 的区域具有柔和实体体积，其余部分逐渐分裂为线条、粒子和节点。

## 视觉层级

从后向前分为五层：

1. 浅灰白基础背景，沿用当前后台的绿色中性色体系。
2. CSS/SVG 数据纹理，包括网格、分子节点、连线和等高线。
3. TresJS/Three.js 多股动态数据流，从偏左上贯穿至偏右下，形成一条松弛的 S 形对角轨迹。
4. 局部白色柔化遮罩，在文字、表格和表单密集区域降低背景对比度。
5. 现有侧栏、顶部栏、卡片、地图和业务内容。

侧栏继续使用不透明深绿色背景，不允许动态背景穿透侧栏。

## 页面状态

同一个全局背景组件根据当前路由切换强度和纹理，不为每个页面创建独立 Canvas。

| 页面类型 | 背景表现 |
| --- | --- |
| 工作台 | 对角数据流最完整，多股轨迹在中部汇聚，并带少量缓慢流动的粒子和数据节点 |
| 资源列表与管理页面 | 保留整体对角方向，但减少实体部分，以细流和数据网格为主 |
| 地图与地理分布页面 | 数据流内部增加极淡的经纬线、节点脉冲和连接路径 |
| 图谱比对与分析页面 | 多股数据流逐渐转化为相互叠加的光谱曲线 |
| 批次详情与溯源页面 | 数据流内部出现顺序节点和链路纹理，暗示时间线与数据链 |
| 表单和编辑页面 | 背景接近静态，仅保留基础纹理 |

页面切换时只渐变颜色、透明度和纹理参数，不做大幅位移或重新入场动画。

## 交互与动效

- 鼠标移动只驱动约 4 至 8 像素的缓慢视差，并通过阻尼插值跟随，避免背景紧贴光标。
- 多股数据流保持非常缓慢的内部流动和汇聚变化，不能产生持续抢夺注意力的波动。
- 页面滚动只带来轻微纵向漂移，不与滚动距离一比一绑定。
- 路由切换使用约 250 至 400 毫秒的柔和参数过渡。
- 动画不影响点击、滚动、地图缩放、拖拽、表单输入或侧栏操作。
- 背景层设置 `pointer-events: none`，交互数据仅由应用壳层监听后传入。

## 组件架构

### `AuthenticatedBackground.vue`

全局背景入口，挂载在 `App.vue` 已登录分支的 `.shell` 内，位于侧栏与工作区内容下方。

职责：

- 读取当前路由并解析背景模式。
- 管理鼠标视差、页面可见性和减少动态效果状态。
- 组合 WebGL 丝带层、SVG 数据纹理层和柔化遮罩层。
- 对外不暴露业务交互，不访问页面数据接口。

### `SpectralRibbonScene.vue`

单一 TresJS Canvas，负责低复杂度多股数据流、局部实体丝带和少量实例化粒子。

职责：

- 根据背景模式更新数据流颜色、聚散程度、弯曲程度、透明度和纹理类型。
- 使用程序化曲线、管状几何体与局部带状几何体，不加载大型外部 3D 模型。
- 在页面隐藏、减少动态效果或低性能模式下暂停或降级。

### `AuthenticatedBackgroundTexture.vue`

使用 SVG/CSS 绘制数据网格、分子节点、经纬线、光谱线和溯源路径。纹理通过预定义模式切换，避免在运行时生成大量 DOM 节点。

### `useAuthenticatedBackground.js`

将路由名称和模块键映射为稳定的背景配置，例如：

```js
{
  mode: "dashboard",
  ribbonOpacity: 0.2,
  texture: "molecular-grid",
  motionScale: 1,
}
```

该 composable 只负责配置解析，便于单元测试。

## 布局集成

- `.shell` 建立独立的层叠上下文并保留当前网格布局。
- 背景固定覆盖整个工作区视口，不增加页面高度，也不参与业务页面布局。
- 对角数据流从偏左上贯穿至偏右下，不能缩成右上角或任一角落的局部装饰。
- 主体约占视口面积的 25% 至 35%，不得铺满整个画面或形成连续高饱和底色。
- `.workspace` 和业务页面保持透明或半透明，使背景可见。
- 面板、表格和表单仍使用实体浅色表面，不改成大面积玻璃拟态。
- 顶部标题区域可以允许更多背景显露，数据密集区域通过遮罩降低背景存在感。
- 数据流经过标题、表格、地图或表单密集区域时，通过透明度、景深和局部白色遮罩退到内容后方，而不是改变业务内容位置。

## 配色

背景保持现有后台品牌色，而不是照搬登录页的高饱和紫粉色：

- 基础背景：`#f5f7f6` 至 `#f9fbfa`
- 主数据流：品牌绿与青色
- 辅助色：低饱和紫色
- 强调色：少量现有陶土橙色
- 纹理线：深绿色或蓝灰色，透明度约 3% 至 8%
- 多股数据流整体透明度约 12% 至 22%，局部实体区域不得形成不透明色块

## 响应式与降级

- 桌面端启用 WebGL 多股数据流、轻微视差和少量粒子。
- 平板端降低曲线数量、几何段数、粒子数量和 DPR，同时保留对角贯穿构图。
- 手机端默认不运行持续 WebGL 动画，显示预渲染或 SVG 静态背景。
- `prefers-reduced-motion: reduce` 下关闭视差、粒子流动和丝带形变，仅保留静态背景。
- WebGL 初始化失败时自动保留 CSS/SVG 背景，页面功能不能依赖 Canvas。

## 性能约束

- 全部认证页面共用一个 Canvas。
- DPR 上限为 1.4。
- 粒子必须使用实例化渲染，数量保持在较低范围。
- 浏览器标签页隐藏时暂停渲染循环。
- 不加载大型纹理、HDR 环境或外部 3D 模型。
- 不为不同路由重复销毁和创建 WebGL 上下文。
- 背景不能降低 Lenis、地图拖拽、表格滚动或表单输入的响应速度。

## 可访问性

- 背景全部标记为装饰性内容，对屏幕阅读器隐藏。
- 背景不改变现有文字与控件的对比度要求。
- 聚焦状态、错误提示、地图标记和交互控件必须始终位于背景之上。
- 高对比度或减少动态效果环境下优先保证信息清晰，不强制保留视觉特效。

## 测试与验收

### 自动化测试

- 路由到背景模式的映射测试。
- 工作台、资源列表、地图、图谱、详情和表单模式均能返回有效配置。
- 未认证状态不渲染 `AuthenticatedBackground`。
- 减少动态效果和 WebGL 不可用时进入静态降级状态。
- 现有认证主题、侧栏和页面组件测试继续通过。

### 视觉与交互验收

- 工作台空白区域明显减少，对角视觉主体横跨整个工作区，但不会压过指标卡和地图。
- 背景不能退化为右上角或其他单一角落的局部装饰。
- 资源列表、表格和表单页面的背景强度低于工作台。
- 侧栏保持实体深绿色且不受背景影响。
- 鼠标视差平缓，不出现紧贴光标或明显晃动。
- 页面切换时背景连续，不闪白、不重新创建 Canvas。
- 桌面、平板和手机布局无溢出、遮挡和点击拦截。

## 明确不包含

- 不修改沉浸式登录首页。
- 不重做侧栏、顶部栏、业务卡片、表格或表单布局。
- 不引入大型第三方 3D 模型或重量级背景依赖。
- 不在业务页面增加与功能无关的文案、卡片或装饰控件。
